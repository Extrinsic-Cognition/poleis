# Mint host adapter

Build `cargo build --release --example mint_adapter --manifest-path poleis/client/Cargo.toml`.
Run the resulting `target/release/examples/mint_adapter` with one JSON request on stdin, then close stdin. The caller must impose a process deadline. The adapter reads at most 256 KiB and emits one JSON line of at most 64 KiB: `{ "ok": true, "result": ... }` or `{ "ok": false, "error": "stable-code" }`. It performs no network requests, file/key reads, signing or submission. Errors contain no supplied values.

All u64 values are canonical decimal **strings**, including slots and lamports. Addresses and hashes use canonical base58. `completionDigest` is nonzero lowercase 64-character hex. `metadata` has exactly `name`, `symbol`, `uri`; the shared byte bounds apply and control characters are refused. Unknown JSON fields are refused.

A `Snapshot` is `{ "address": "base58", "account": null }` for an absent RPC account, or `{ "address": "base58", "account": { "owner": "base58", "lamports": "123", "dataBase64": "...", "executable": false } }`. Each data value is limited to 16 KiB. The host must verify the pinned mainnet genesis and deployed program code/authority and obtain all snapshots at one coherent RPC context and commitment. Successful decoding is not a chain proof or eligibility attestation.

## Methods

- `derive`: fields `unit`, `buyer`, `completionDigest`. Returns the canonical 14 mint instruction `accounts`, 11 `readAddresses` (buyer, config, curve, registry, treasury, receipt, mint, initial token, hook validation, fund, tally), named `curve`, `mint`, `seat`, `token`, `validation`, and `program`, `programData`, `genesisHash`. The initial token address is not a current-owner lookup after resale.
- `inspectSale`: the three identity fields above, plus `metadata`, `currentSlot`, `maxPriceLamports`, `expirySlot`, `accounts` (exactly the 11 snapshots in `readAddresses` order). Authenticates owners, addresses, bumps, layouts, sale mode, root/unit, freeze/capacity/window, price ceiling and fresh issuance accounts. Returns the derive result plus `sale` (`unit`, `startLamports`, `stepLamports`, `mintedCount`, `capacity`, `opensSlot`, `closesSlot`, `completionIssuer`, `genesisHash`), `config` (`root`, `authority`, numeric `mode`), `quote` (`priceLamports`, `fundFeeLamports`), `issuer`, `permitBase64`, `buyerLamports`, and `allocations` (`address`, numeric `size`, `currentLamports`). Fund fee is included in the mint price. Allocations are rent targets; the host queries rent exemption and sums `max(0, minimum-currentLamports)`. Tally rent conservatively covers any price within the approved cap. For an initial quote use `expirySlot=currentSlot`, then repeat the pure inspection on the same snapshots with the chosen bounded expiry and actual price ceiling before obtaining an issuer signature.
- `buildMint`: the identity fields, `metadata`, `currentSlot`, `maxPriceLamports`, `expirySlot`, `curve` snapshot, `issuerSignatureBase64`, `recentBlockhash`. Regenerates the canonical permit, verifies its issuer signature and uses the existing mint instruction builder plus Solana's official legacy message compiler/serializer. Returns derive fields plus `transactionBase64` (one zero buyer signature), `messageBase64`, `permitBase64`, `metadataDigest`. No caller-provided arbitrary instruction or permit bytes are accepted. The host independently rechecks the full sale, completion revisions, blockhash validity, rent, network fee and total balance; this method alone is not mint authorization.
- `inspectReceipt`: identity fields, `metadata`, `maxPriceLamports`, `receipt` and `mint` snapshots, optional `token` snapshot or null. Returns `{ "state": "absent" }` only when both canonical receipt and mint are absent/fresh. Otherwise the existing strict receipt validator returns `state:"issued"`, `mint`, `receipt`, `originalBuyer`, `paidLamports`, `serial`, `owner` (base58 or null), `burned` (boolean), `ownership` (`"held"`, `"not-observed"`, `"burned"`). Supplying a token means asking it to prove the current holding; an emptied initial account after resale is rejected, so omit it when no actual current token account is known. A burned immutable mint still has an issuance receipt. No transaction signature, confirmation status, signer authority or live registry membership is inferred.

`inspectSale` and `buildMint` require `currentSlot <= expirySlot < closesSlot`; program execution remains authoritative and may reject a stale quote or blockhash. The adapter never substitutes for issuer eligibility, wallet review, wallet signature, RPC confirmation, or deployment authentication.

Host checks: `cargo test --example mint_adapter --locked`. Independent SVM and Node integration should feed genuine fixture account outputs through the compiled adapter and the wallet transaction verifier.
